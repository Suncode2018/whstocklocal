# ตารางกำหนดสิทธิ์ผู้ใช้

Admin → จัดการผู้ใช้งาน → ปุ่ม “กำหนดสิทธิ์”

1. เลือกผู้ใช้
2. กำหนด Desktop หรือ HH อย่างใดอย่างหนึ่ง
3. ติ๊กสิทธิ์ในตาราง: ดูข้อมูล / สร้าง–บันทึก / ยืนยันรายการ / ส่งออก
4. บันทึกสิทธิ์ทั้งหมดครั้งเดียว

เลือกสิทธิ์ทำรายการจะเปิด “ดูข้อมูล” ให้อัตโนมัติ หากเอาดูข้อมูลออก สิทธิ์อื่นในแถวนั้นจะถูกล้าง
ช่อง “—” คือเมนูไม่รองรับการทำงานนั้น ช่องที่เลือกไม่ได้มีคำอธิบายว่า Role ไม่อนุญาต
Admin เข้าจัดการระบบได้ครบเสมอ จึงเปิดตารางเพื่อดูได้แต่ไม่ถูกจำกัดสิทธิ์

## ตัวอย่างการบังคับสิทธิ์

- รับสินค้า: สร้างใบรับใช้สร้าง/บันทึก; ยืนยันรับเข้าสต๊อกใช้ยืนยันรายการ
- PUTAWAY: สร้าง/ยกเลิกแผนใช้สร้าง/บันทึก; ยืนยันย้ายสต๊อกใช้ยืนยันรายการ
- PICK / TRANSFER: รายการบันทึกย้ายหรือตัดสต๊อกจริงใช้ยืนยันรายการ ไม่มีขั้นตอนบันทึกร่าง
- Delivery: สร้าง/ยกเลิกร่างใช้สร้าง/บันทึก; ส่งจริง/รับปลายทางใช้ยืนยันรายการ; พิมพ์/PDF ใช้ส่งออก
- ตรวจนับ: บันทึกผลใช้สร้าง/บันทึก; ยืนยันปรับยอดต้องเป็น Admin ตาม Role เดิม
- ตรวจสต๊อกตาม BOM: กดตรวจเป็นดูข้อมูล แม้ API ใช้ POST เพราะไม่ได้แก้สต๊อก
- Export CSV ตรวจสิทธิ์ส่งออกกับ API ก่อนสร้างไฟล์
- หากถอดสิทธิ์การทำงาน API จะปฏิเสธทันที และหน้าเว็บปรับปุ่มเมื่อโหลดสิทธิ์ใหม่

## การอัปเดต

เครื่อง dev เพิ่มคอลัมน์และทดสอบแล้ว ให้หยุดด้วย Ctrl+C และรัน npm start ใหม่ จากนั้น Ctrl+F5

เครื่อง 5555 ที่มีระบบ UserNavigation แล้ว: รัน PermissionMatrix.sql ใน dbMaster แล้ว Restart-Service WHStock5555
เครื่องที่ยังไม่มีระบบเมนู: รัน UserNavigation.sql ฉบับล่าสุด ซึ่งรวมคอลัมน์สิทธิ์และเงื่อนไขหนึ่งช่องทางแล้ว

เมนูที่กำหนดไว้เดิมจะรักษาสิทธิ์เดิมภายใต้ Role จนกว่า Admin จะปรับตาราง ไม่เปลี่ยนรหัสผ่านหรือยอดสต๊อก
ประวัติการบันทึกสิทธิ์เก็บใน dbMaster.dbo.UserAccessAudit พร้อมผู้ทำรายการและค่าก่อน/หลัง
