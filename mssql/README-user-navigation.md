# Login อัตโนมัติตามช่องทางที่ Admin กำหนด

หน้า Login หลัก: /index.html
ผู้ใช้กรอก username/password เท่านั้น ระบบอ่านช่องทางจากฐานข้อมูล ไม่รับโหมดจากหน้าเว็บ แล้วส่งเข้า Desktop หรือ HH อัตโนมัติ

## Admin ตั้งค่า

Admin → จัดการผู้ใช้งาน → ช่องทาง / เมนู → เลือก Desktop หรือ HH อย่างใดอย่างหนึ่ง → เลือกเมนู → บันทึก

- บัญชี Admin ใช้ Desktop และเข้าจัดการระบบได้ครบเสมอ
- ผู้ใช้ทั่วไปกำหนดได้หนึ่งช่องทางต่อคน
- ค่าเริ่มต้นเมื่อยังไม่ได้ตั้งรายคน: OPERATOR เป็น HH; ADMIN/POWERUSER/SUPERVISOR/VIEWER/READONLY เป็น Desktop
- ผู้ใช้ที่เดิมถูกปิดทั้งสองช่องทางยังถูกปิดไว้จนกว่า Admin จะกำหนดใหม่
- Role ยังคุมการแก้ไข Master และการยืนยันงานสำคัญ เมนูที่ Role ไม่รองรับเลือกไม่ได้
- หลัง Admin เปลี่ยนช่องทางหรือสิทธิ์ ให้ผู้ใช้ออกจากระบบและ Login ใหม่
- Token ของโหมดเดิมเข้าถึง API ไม่ได้เมื่อ Admin เปลี่ยนช่องทาง แม้ Permissions งานคลังเท่าเดิม
- URL Login เดิม /desktop/login.html และ /handheld/login.html จะส่งมาหน้า Login เดียว และไม่สามารถใช้บังคับโหมดได้

## อัปเดต

เครื่อง dev รัน SQL แล้ว ให้ Ctrl+C → npm start และกด Ctrl+F5 / ออกจากระบบแล้ว Login ใหม่

เครื่อง 5555 ที่เคยติดตั้งระบบเมนูแล้ว: รัน UserAssignedMode.sql ใน dbMaster แล้ว Restart-Service WHStock5555

เครื่องที่ยังไม่มีตารางระบบเมนู: รัน UserNavigation.sql ฉบับล่าสุดแทน ซึ่งรวมเงื่อนไขหนึ่งโหมดไว้แล้ว

UserAssignedMode.sql จะปรับโปรไฟล์เดิมที่เปิดทั้งสองโหมดให้เป็น Desktop โดยคงเมนูและรหัสผ่านเดิมไว้ โปรไฟล์ HH-only และโปรไฟล์ปิดใช้งานไม่เปลี่ยน
